# HDSI Android 0.1.0-preview.9.7.1

本版修复代码审查发现的消息传输、存档一致性、历史搜索与发布流程缺陷。Android versionCode 为 **37**，HDS 引擎仍为 **1.0.1-rc57**，沿用现有包名与签名。

## 修复与理由

| 问题 | 用户影响 | 本版处理 |
| --- | --- | --- |
| RPC 对每个网络分块分别解码 UTF-8 | 中文或 emoji 的字节跨分块时会变成替换字符；可能影响聊天、搜索及设置 | 先按字节收集完整请求，再统一解码；保留 1 MiB 请求限制 |
| 存档包含 `card.source`，恢复和本机备份却遗漏它 | 原件缺失时，恢复后仍无法重新导出完整存档；角色元数据与原件不能一起回滚 | ZIP 恢复、本机备份和事务恢复均包含原件；旧本机备份及旧恢复日志继续兼容 |
| 导出回调临时读取当前角色 | 文件选择期间切换角色后，可能导出与确认对象不同的故事 | 从界面传递确认时的角色 ID，执行时检查角色是否仍一致 |
| 新搜索失败后提前替换了翻页条件 | 旧结果的游标搭配新条件，后续页混杂、漏项或反复失败 | 只有成功读取后才提交搜索条件，与显示结果一起更新 |
| 发布工作流写死 9.7 | 升级版本后发布失败；同版本后续提交也会重复创建 Release | 从 package 版本生成附件名、tag 和说明路径；验证 npm/Android/说明一致；已存在的 Release 保持原附件 |

## 验证与边界

- 网络回归通过真实鉴权 HTTP RPC，故意从中文和 emoji 字节中间分块，并检查超限请求仍被拒绝。
- 浏览器回归覆盖“搜索成功 → 更换条件但失败 → 沿原条件翻页 → 重试新搜索”，继续覆盖 250 条历史、阅读位置、320px 界面、隐藏页面轮询及首次对话。
- Android 单元测试覆盖原件缺失后的 ZIP 恢复与再次导出、本机备份、重复执行中断回滚，以及缺少原件的旧本机备份。
- 发布版本校验覆盖 Android、npm 锁文件及说明不一致时拒绝发布。
- 发布仍以宿主测试、类型检查、Android 编译/lint/单元测试、ARM64/PRoot/QQ 无账号冒烟及 APK 签名校验通过为前提。
- 本轮不代表已完成真机覆盖安装、锁屏续航或真实 QQ 账号验收；步骤仍见 [TEST-ON-PHONE.md](TEST-ON-PHONE.md)。

## 后续改进建议

1. **优先补充真机发布门槛。** 浏览器模拟和 Robolectric 无法覆盖国产 ROM 后台限制、SAF 文件提供商、录音权限与覆盖安装行为。至少固定一台 Android 8/较旧系统及一台当前国产 ROM 做升级、恢复、锁屏回归，并记录结果。
2. **给动态和本机备份增加历史管理与空间统计。** `runtime/feed.ts` 当前只返回最近 200 条，但 JSON 内仍保留全部动态；`StoryArchive` 持续保留本机备份。长期使用会累积数据，旧动态也缺少翻页入口。后续应提供分页、占用统计和用户明确选择的清理，而非自动删除故事。
3. **逐步缩小上游类型诊断基线。** 当前显式保留 133 条上游诊断能阻止新增问题，却没有消除既有接口风险。建议按 Koishi 接口、Schema 默认值、可选字段分批修复，每批减少基线并补对应行为测试。
4. **拆分宿主和主界面的职责。** `runtime/host.ts` 同时处理鉴权、角色生命周期、聊天、媒体和管理 RPC；`apps/mobile-ui/main.tsx` 集中页面与大量异步状态。按 RPC 传输、故事会话、历史读取等稳定边界拆分，有助于隔离故障并减少后续修改的回归范围。
